### DSH-0.1.5-A2-01 · `workspaceFiles` drops the `Agent` first parameter for a Typert `workspaceFileScope` lookup; client resource type, `reload`/`restat`, and `absolute` scope authorization all change

- **Type**: breaking
- **Applies to**: Host plugins that inject or call the `workspaceFiles` service, Web Client
  plugins that consume the `file` resource (`useResource<'file'>`) or construct the file
  resource provider, and tests that mock the Remote.
- **Touchpoints**: #3, #6
- **Action level**: required-if-hit
- **Symptoms**: the previous edge shipped `workspaceFiles.*(agent, path, …)`; at
  `0.1.5-alpha.2` the first parameter is a `WorkspaceFileScope` resolved by the Typert
  lookup `workspaceFileScope` (`packages/api/workspace-files/src/index.ts`:
  `static inject = ['fs','sandboxPolicy','sessions','typert']`, lookup registered next to
  the Remote). Every method changes signature and two new methods appear (`readAll`,
  `readRelated`). On the client, the `file` resource value becomes `WorkspaceFileStat`
  (the `changed` field is gone), the `WorkspaceFileResource`/`SessionLookup` exports are
  removed, `reload(address)` plus `ChangeFeed.requestRestat` and the `{kind:'restat'}`
  notice are deleted, and the provider factory is
  `createFileResourceProvider(remote, changes)` with the plugin's inject list dropping
  `sessions` (`['resources','remote','remote.workspaceFiles']`). Address handling changes
  too: an `absolute` scope address no longer authorizes a Host call and always returns
  `workspace-file/unknown-workspace`; `fileAddressFor()` routes out-of-workspace absolute
  paths through the `session` scope, `sessionFileAddress()` keeps the leading `/`, and
  `parseFileAddress()` is now handwritten prefix parsing that ignores `?`/`#` and does not
  resolve `.`/`..`.
- **Migration recipe**: on the client, pass the session id only (the lookup resolves the
  scope), stop calling `reload`/`restat` and decide staleness from `version`, and update
  types to `WorkspaceFileStat`. On the Host, inject `sessions` (plus
  `sessionPersistence` when cold sessions must resolve) and never pass an Agent; expect
  `gateway/lookup-not-found` if the lookup cannot resolve. Absolute paths must be
  addressed in the `session` scope; treat `unknown-workspace` as the documented outcome for
  `absolute`. Normalize `.`/`..` yourself before calling `parseFileAddress()`.
- **Verification**: typecheck passes with the new signatures; a session-scoped file address
  resolves through the Remote; an `absolute` address returns `workspace-file/unknown-workspace`;
  a `reload` reference no longer compiles; `createFileResourceProvider(remote, changes)`
  compiles with the two-argument call.
- **Source**: [alpha.2 `api/workspace-files/src/index.ts` (scope lookup, `readAll`/`readRelated`)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/api/workspace-files/src/index.ts) · [alpha.2 `client/types.ts` (`WorkspaceFileStat`)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/api/workspace-files/src/client/types.ts) · [alpha.2 `client/provider.ts` (absolute scope, no reload)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/api/workspace-files/src/client/provider.ts) · [alpha.2 `util/workspace-path/src/index.ts` (`fileAddressFor`)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/util/workspace-path/src/index.ts) · [alpha.2 `file-address.ts` (`parseFileAddress`)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/util/workspace-path/src/file-address.ts) · [0.1.5-alpha.2 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.5-alpha.2)

### DSH-0.1.5-A2-02 · file reads are no longer confined to the workspace root (`outside-workspace` now applies to listings only), with a new `maxFileBytes` cap and `readAll`/`readRelated`

- **Type**: security
- **Applies to**: Host deployments that expose file content to users through the
  `workspaceFiles` surface (previews, editors, chat file links) and any plugin that assumed
  the read path was workspace-confined.
- **Touchpoints**: #4, #3
- **Action level**: required-if-hit
- **Symptoms**: `locateFile` no longer calls `confine(...)`; reads follow the composed
  filesystem's read access **including paths outside the workspace**
  (`packages/api/workspace-files/src/index.ts`), and `workspace-file/outside-workspace` now
  applies only to directory listings. The package README states the boundary explicitly:
  the sandboxing backend fences writes and edits, not reads. A new config key
  `maxFileBytes` (default 32 MiB) caps the new `readAll`/`readRelated` methods, which fail
  with `too-large` instead of truncating; `readRelated` resolves relative paths from the
  base file's directory (including out of workspace).
- **Migration recipe**: stop treating workspace containment as the read boundary — the
  effective boundary is the composed `ctx.fs` plus the sandbox policy, so review which
  backends a deployment mounts and what read access they grant. Set `maxFileBytes`
  deliberately for the deployment (it bounds the new whole-file reads). When a plugin
  serves file content to a user, re-check that the paths it accepts are the paths you
  intend to expose; if a workflow needs containment, enforce it in the plugin rather than
  relying on the service.
- **Verification**: reading a path outside the workspace root succeeds through the composed
  filesystem, while listing a directory outside the root still returns
  `workspace-file/outside-workspace`; a read above `maxFileBytes` fails with `too-large`
  (no truncated content); the deployment's backend read policy is recorded in the
  migration notes.
- **Source**: [alpha.2 `api/workspace-files/src/index.ts` (`maxFileBytes`, unconfined `locateFile`)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/api/workspace-files/src/index.ts) · [alpha.2 `api/workspace-files/README.md` (reads may target paths outside the workspace)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/api/workspace-files/README.md) · [alpha.1 `api/workspace-files/src/index.ts` (confined read, for contrast)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/api/workspace-files/src/index.ts) · [0.1.5-alpha.2 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.5-alpha.2)

### DSH-0.1.5-A2-03 · the `conversation` slot moves under the new root-scoped `main` keyed slot; global panels register through `sidebar.panellist`

- **Type**: breaking
- **Applies to**: Web Client plugins that registered into the `conversation` slot or that
  add a global sidebar panel.
- **Touchpoints**: #6, #5
- **Action level**: required-if-hit
- **Symptoms**: `ui-layout` replaces its single `'conversation'` slot
  (`{ kind:'single'; scope:'session-maybe' }` at alpha.1) with a root-scoped keyed slot
  `'main': { kind:'keyed'; scope:'root' }` whose **reserved `conversation` key hosts the
  Conversation**; other keys receive no Session binding. `ui-conversation` registers
  `'main.conversation'`, and a new root-scoped list slot `'sidebar.panellist'`
  (`owner: SidebarPanelIconOwnerProps`) lets a plugin contribute an icon entry
  (`id`, optional `order`, string or locale-aware `label`) that addresses the panel body
  registered in `main` under the same key. `SidebarRootInjected` gains `selectPanel(id)`
  and `hooks.panels`; selecting a missing `main` entry throws without changing the current
  selection, and with no registrations neither the list nor its spacing renders.
- **Migration recipe**: move conversation-slot registrations to `'main.conversation'`;
  register a global panel as an icon in `'sidebar.panellist'` plus a body in `'main'` with
  the same key. Read the selected state through `usePanelInfo`, and keep the `main` key
  registered whenever the panel can be selected (selecting a missing key throws).
- **Verification**: a panel icon appears and selecting it renders the `main[key]` body; the
  conversation renders at the reserved `conversation` key; selecting an unregistered key
  throws and leaves the previous panel selected; zero registrations render no list.
- **Source**: [alpha.2 `client/ui-layout/src/client/index.ts` (`main` keyed slot)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/client/ui-layout/src/client/index.ts) · [alpha.1 `client/ui-layout/src/client/index.ts` (old `conversation` slot)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/client/ui-layout/src/client/index.ts) · [alpha.2 `client/ui-sidebar/src/client/contract/slots.ts` (`sidebar.panellist`)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/client/ui-sidebar/src/client/contract/slots.ts) · [alpha.2 `client/ui-sidebar/README.md` (panel contract)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/client/ui-sidebar/README.md) · [0.1.5-alpha.2 release notes (Web plugin panel API)](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.5-alpha.2)

### DSH-0.1.5-A2-04 · minimal profiles become persistent-shell-only (`str_replace_editor` is opt-in; the bare filesystem group is gone)

- **Type**: behavior
- **Applies to**: profile compositions and plugins that assumed the `minimal` preset or
  `sdk-minimal` bundle mounts an editor tool by default.
- **Touchpoints**: #5
- **Action level**: conditional
- **Symptoms**: the `minimal` agent preset is now described as a "single-tool
  coding-agent composition": the model receives only the platform persistent shell (`bash`
  on POSIX, `pwsh` on win32) — the `str_replace_editor` row and the bare local filesystem
  group are removed (`packages/preset/agent-presets/presets/minimal/agent.cordis.yml`).
  The `sdk-minimal` bundle patch likewise drops the `fs-local` and
  `str-replace-editor` rows (`packages/bundle/sdk-minimal/cordis.patch.yml`), and its
  package dependencies lose `dsh-fs-local` / `dsh-tool-str-replace-editor`. The bash tool
  description now says network access depends on the task environment (prefer configured
  mirrors/proxies) instead of claiming a package mirror. `str_replace_editor` remains
  available by explicit opt-in patch, and the CLI reference documents the new stance; the
  persistent-shell completion/timeout reporting is also unified.
- **Migration recipe**: if a workflow needs file editing in a minimal profile, add an
  explicit patch mounting the editor tool (see the CLI reference and the SDK smoke test's
  opt-in case) instead of assuming it ships. Re-check any prompt or tool-guidance text that
  promised an editor or a package mirror in these profiles.
- **Verification**: `dsh --profile <minimal-profile> --dump-config` lists only the
  persistent shell tool rows; the opt-in patch adds `str_replace_editor`; a filtered
  subagent no longer receives guidance for the removed tools (see
  [DSH-0.1.5-A2-07](v0.1.5-alpha.2.md)).
- **Source**: [alpha.2 `presets/minimal/agent.cordis.yml` (single-tool composition)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/preset/agent-presets/presets/minimal/agent.cordis.yml) · [alpha.2 `bundle/sdk-minimal/cordis.patch.yml` (rows removed)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/bundle/sdk-minimal/cordis.patch.yml) · [alpha.2 `apps/cli/reference/README.md` (minimal-profile stance)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/apps/cli/reference/README.md) · [0.1.5-alpha.2 release notes (minimal-profile default tools)](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.5-alpha.2)

### DSH-0.1.5-A2-05 · two new non-ignorable session events make alpha.2 sessions unreadable by older harnesses; `feedback/record` payload and subagent catalog semantics change

- **Type**: breaking
- **Applies to**: anything that reads stored Session logs across harness versions, writes
  feedback events, or consumes the subagent catalog.
- **Touchpoints**: #2
- **Action level**: required-if-hit
- **Symptoms**: `deliverables/presented` and `subagent/catalog` join
  `KNOWN_SESSION_EVENT_TYPES` **without** an `ignorable` marker, and
  `packages/session/session-persistence/src/storage-contract.ts` refuses unknown
  non-ignorable events ("unknown to this harness and not marked ignorable; refusing to
  interpret the log — it was likely written by a newer harness"). Because
  `Session.append()` has no `ignorable` channel, a producer cannot mark these events, so an
  **older harness (including `0.1.5-alpha.1`) cannot read a session that contains them** —
  one-way readability within the same V3 format. In addition, `feedback/record` changes
  from `{ text: string }` to `{ text?, category? }` and `recordFeedback(session, text)`
  becomes `recordFeedback(session, entry)`; subagents now persist a catalog entry
  (`subagent/catalog`, projection `subagentCatalog` at `stateVersion: 2`), and a catalog
  append failure disposes the run and surfaces the error to the caller.
- **Migration recipe**: keep read and write harness versions aligned across a session store
  — do not expect an older build to read sessions written by alpha.2, and do not hand-write
  the new event types. Update feedback callers to the entry object (optionally with
  `category`). When consuming subagent state, read the `subagentCatalog` projection and
  handle a disposed run when catalog persistence fails.
- **Verification**: an `0.1.5-alpha.1` build refuses a session containing the new events
  with the documented error; `recordFeedback(session, { text })` compiles and writes a
  `feedback/record` entry; the `subagentCatalog` projection populates after a subagent is
  created.
- **Source**: [alpha.2 `core/session/src/known-event-types.ts` (two new events)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/core/session/src/known-event-types.ts) · [alpha.2 `session-persistence/src/storage-contract.ts` (refusal path)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/session/session-persistence/src/storage-contract.ts) · [alpha.2 `feedback/command-feedback/src/index.ts` (`FeedbackRecord`)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/feedback/command-feedback/src/index.ts) · [alpha.2 `subagent/subagent/src/catalog.ts` (`subagent/catalog`)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/subagent/subagent/src/catalog.ts) · [0.1.5-alpha.2 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.5-alpha.2)

### DSH-0.1.5-A2-06 · `dsh-llm-pi-ai` config/type changes (optional `piProvider`, required `modelErrors`, `deferred` resolution) and provider-level `error`

- **Type**: breaking
- **Applies to**: plugins that construct or read `ResolvedPiAiProviderProfile`, call
  `resolveRouteModels`/`assertServiceable`, or surface provider diagnostics.
- **Touchpoints**: #3, #1
- **Action level**: required-if-hit
- **Symptoms**: `ResolvedPiAiProviderProfile.piProvider` becomes optional, `modelErrors`
  becomes a required `ReadonlyMap<string,string>`, and `catalogError?` is added
  (`packages/llm/llm-pi-ai/src/config.ts`); `resolveRouteModels(request, validation)` takes
  a `'strict' | 'deferred'` validation mode, `assertServiceable(config, previous?)` takes
  the previous config, and `PiAiCatalogError` is a new export (`src/catalog.ts`). Stored
  configurations that drift after a catalog change no longer hide the whole model-settings
  entry: profiles resolve with `'deferred'` so per-model errors are preserved, writes
  validate only changed providers, and requesting a broken model fails with
  `INVALID_CONFIG` while other models keep working. `LlmConfigurableProvider.error?: string`
  surfaces a provider-level diagnostic (`packages/llm/llm/src/types.ts`).
- **Migration recipe**: null-check `piProvider` before use and handle `modelErrors` /
  `catalogError` instead of assuming a serviceable profile; update
  `resolveRouteModels`/`assertServiceable` call sites to the new signatures; surface
  `LlmConfigurableProvider.error` in provider lists rather than hiding the provider.
- **Verification**: a drifted stored config still shows the settings entry with per-model
  errors; a request for a broken model fails with `INVALID_CONFIG` while a healthy model
  succeeds; a provider-level `error` renders in the settings surface.
- **Source**: [alpha.2 `llm-pi-ai/src/config.ts` (`piProvider?`, `modelErrors`, `assertServiceable`)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/llm/llm-pi-ai/src/config.ts) · [alpha.2 `llm-pi-ai/src/catalog.ts` (`resolveRouteModels`, `PiAiCatalogError`)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/llm/llm-pi-ai/src/catalog.ts) · [alpha.2 `llm-pi-ai/src/adapter.ts` (`INVALID_CONFIG` path)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/llm/llm-pi-ai/src/adapter.ts) · [alpha.2 `llm/src/types.ts` (`LlmConfigurableProvider.error`)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.2/packages/llm/llm/src/types.ts) · [0.1.5-alpha.2 release notes (pi-ai config diagnostics)](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.5-alpha.2)

### DSH-0.1.5-A2-07 · tool guidance sections follow the visible tool set per scope

- **Type**: behavior
- **Applies to**: plugins that contribute system-prompt guidance for tools, and any
  workflow relying on filtered subagents.
- **Touchpoints**: #5
- **Action level**: conditional
- **Symptoms**: the `read`/`write`/`edit`/`glob`/`grep` guidance sections in
  `tool-fs` and `tool-fs-search` now render conditionally:
  `text: ({ scope }) => ctx.tools.get(name, scope) === undefined ? '' : …`, so a subagent
  whose tools were filtered no longer receives instructions for tools it cannot use
  (`write` only recommends `edit` when `edit` is visible; `grep` only mentions reading
  context when `read` is visible). The functional `text` signature itself already existed
  at alpha.1; this edge is where the first-party tools adopt it. Scope-dependent **schema**
  wording is explicitly not implemented — tool schemas stay static.
- **Migration recipe**: apply the same pattern to your own guidance sections (render only
  when `ctx.tools.get(name, scope)` resolves), and do not rely on guidance text as evidence
  that a tool is mounted. Keep schema descriptions accurate for all scopes since they
  cannot vary per scope.
- **Verification**: a filtered subagent's prompt contains no guidance for the filtered
