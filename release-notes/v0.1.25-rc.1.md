# v0.1.25-rc.1

Adds support for DeepSeek Harness `0.2.1-rc.2` and makes the Git build artifacts reproducible on Windows checkouts.

## Harness 0.2.1-rc.2

`0.2.1-rc.2` is a maintenance release of the `0.2.1` line. Comparing all 25 packages this plugin
depends on, both cohorts ship the **same 760 files, with zero code or type-declaration
differences** — only `package.json` changes, and only in version and version-pinned dependency
ranges. Every API this plugin consumes is therefore unchanged:

- member creation (`startActivation` / continuable fallback)
- host FIFO and steer delivery, plus `sendMessage`
- `agent/created` startup admission and the legacy `agent/session-start` seam
- targeted child drain (`drainChildren`)
- `tools.view()` restrictable names, member tool policies and captain-only denial
- session own-event reads and the stored session format generation

Because the surface is identical, this release changes no runtime behavior. It moves the exact
supported cohort, the development dependency closure and the pnpm overrides to `0.2.1-rc.2`, and
records the byte-level comparison as migration evidence. `0.2.1-rc.1` remains supported and is
now listed as the previous recommended RC.

## Windows artifact reproducibility

`scripts/git-artifacts.mjs` hashes raw file bytes to prove that committed `lib/` matches the build.
The repository had no `.gitattributes`, so a Windows checkout with `core.autocrlf=true` rewrote
tracked text files to CRLF while the committed stamp was produced from LF files upstream. The
check therefore failed on every Windows clone. A `.gitattributes` now pins `eol=lf` for tracked
text, so the digest is platform-independent.

## Compatibility

- Harness `0.2.1-rc.2` (recommended), `0.2.1-rc.1`, `0.2.0-rc.2`, `0.1.7-rc.2`, `0.1.5-rc.1`,
  `0.1.5-rc.2`, `0.1.5-rc.3`, `0.1.2-rc.1`, `0.1.2-alpha.5`, `0.1.2-alpha.2`
- Node `^22.19.0 || >=24` (unchanged)

No migration step is required for existing `0.1.24-rc.1` users on `0.2.1-rc.1`. Install this
version when the host is `0.2.1-rc.2`.
