### DSH-0.1.2-A3-01 · New capability: plugin settings card via `settings.plugin.item` keyed slot

- **Type**: capability
- **Applies to**: Web Client plugins that want an in-page card in the official Settings → Plugins panel (a `settings.plugin.item` keyed slot whose key equals the plugin's settings namespace)
- **Touchpoints**: #3, #5
- **Action level**: optional
- **Symptoms**: none for existing plugins — the surface is additive; adopting it changes where users edit plugin options (in-page card vs raw `<dshHome>/settings.yaml`) and how the plugin's Node half exposes the option list.
- **Migration recipe**: register the plugin's settings namespace through the Node half (`settings` service, same-named namespace the plugin already uses), then have the client render a card into `settings.plugin.item[key = namespace]`; the card reads/updates via the declared schema instead of ad-hoc files; keep the full option list available in `settings.yaml` for advanced knobs and document which subset the card shows; changes apply live (saved state is re-read by the running plugin — no restart).
- **Verification**: open Settings → Plugins, find the plugin's card, toggle/change a field, and confirm the running plugin reacts without a web restart; verify the packed client artifact contains the card entry, not just the source.
- **Source**: [alpha.2/alpha.3 plugin-owned settings surface design](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.2-alpha.3/.agents/notes/implemented/architecture/2026-08-12-plugin-owned-settings-surface.md) · [whale-girl 4fe5792 — settings card integration](https://github.com/vlln/whale-girl/commit/4fe5792c6f873c6b3a29dd12198ba47a397e17f3) · [dsh-loop 488b574 — per-tool dynamic settings registration](https://github.com/vlln/dsh-loop/commit/488b574c1603320cc078024ea5ee2aea9a3ceff6)
- **Field note** (2026-08-31, whale-girl): the first integration implemented a high-frequency subset of 7 fields (show-on-page, size, opacity, wandering, sleep delay, feed/play reply pools) as two new client modules (settings-card 298 lines, settings-form 165 lines) plus 148 lines of tests and an 81-line decision record; the packed `lib/client.js` grew 543 lines total. A companion integration in dsh-loop ([488b574 — per-tool dynamic settings registration with a self-drawn switch](https://github.com/vlln/dsh-loop/commit/488b574c1603320cc078024ea5ee2aea9a3ceff6)) — two plugins adopting the same public seam independently is the strongest available evidence that the seam is stable enough to shape plugins around.

## Corridor finding: no breaking plugin changes (one additive capability)

- **Scale**: 117 commits between the two tags, mostly web client (turn rail, session
  projection) and session work.
- **Per-package verification** — every runtime API surface third-party plugins touch,
  compared at the two tags:
  - `@deepseek-ai/dsh-tools` (defineTool / register / ToolDefinition),
    `credentials`, `llm`, `agent`, `settings`, `host/webserver` (`WebRoute`),
    `vendor/cordis`: only `package.json` version bumps, no source changes.
  - `@deepseek-ai/dsh-client-connection`: the host RPC face plugins use
    (`rpc.ts` handle / intercept) is unchanged; its client-side transport
    (`src/client/connection.ts`) has one non-plugin-face change — a stalled
    transport-ready wait now logs a warning instead of aborting the connection
    generation.
  - `bundle/web-app` patch layer adds one built-in row, `session-turn-outline`
    (`@deepseek-ai/dsh-session-turn-outline`), for the whole-log turn rail. The row is
    bundle-internal; third-party plugin loading is unaffected.
- **Additive capability (this PR)**: the web client's Settings → Plugins panel gains a
  `settings.plugin.item` keyed-slot seam so plugins can render an in-page settings card.
  This is additive — no existing plugin face breaks (the batch re-validation below ran
  with zero code changes) — and is recorded as DSH-0.1.2-A3-01 for plugins that want
  the richer surface. Recorded by vlln plugin migrations (whale-girl, dsh-loop) as an
  independent addition to the corridor file that originally carried no cards.
- **npm channels**: the `alpha` dist-tag now resolves to `0.1.2-alpha.3`;
  `latest`/`next` still resolve to `0.1.1-rc.2`.
- **Batch re-validation**: the 17 omdsh-dev plugin repositories passed
  typecheck/tests/build and a real-harness tool smoke against a source checkout of
  `dsh-v0.1.2-alpha.3` with **zero code changes**. The only defect found (a
  `session_health` stats input check) is plugin-internal and unrelated to this edge.
- **Conclusion**: treat this edge as a no-op corridor for **breaking** migration; the
  additive settings-card seam is documented above as DSH-0.1.2-A3-01 for plugins that
  want the richer surface.
