# v0.1.26 — Team workspace and input compatibility fixes

Stable plugin release on npm `latest`; recommended host: Harness `0.2.1-rc.2`.

- Refresh the embedded team workspace with light cards, responsive member/task columns, a completion summary and the captain's latest unread messages. Preserve dark mode, keyboard access and existing team controls. ([#266](https://github.com/NanmiCoder/dsh-agent-teams/pull/266))
- Display claimed tasks separately from open, blocked and running tasks. This corrects the visual projection; it does not claim to resolve every cause of a task remaining claimed. ([#264](https://github.com/NanmiCoder/dsh-agent-teams/pull/264))
- Treat a gateway-materialized empty inline plan and empty optional member fields as omitted, and normalize an empty optional task assignee before claiming. ([#242](https://github.com/NanmiCoder/dsh-agent-teams/pull/242))
- Detect stored session formats from the live host, including after session-module replacement, and retain legacy message compatibility. ([#240](https://github.com/NanmiCoder/dsh-agent-teams/pull/240))
- Retain the exact host support matrix, committed Git installation artifacts and script-free Git installation path.

In desktop plugin settings, install `@nanmicoder/dsh-agent-teams@0.1.26` and enable it. Follow the host's restart prompt when appropriate for your running work. For a CLI-managed profile:

```sh
dsh plugin --profile web add --save-exact @nanmicoder/dsh-agent-teams@0.1.26
```

Replace `web` with your CLI profile and restart that profile's Harness process after installation. Plugin and host versions are independent; this release does not upgrade the host.

The release workflow requires Ubuntu and Windows static checks plus all ten exact Harness targets using the same candidate tarball. Runtime scenarios use real Harness sessions, tools and sub-agents with deterministic model fixtures. The UI was also exercised in a macOS Harness Web host; this does not establish native Windows Desktop or every real-provider behavior. See the [maintenance guide](../docs/maintenance-workflow.md) for the full scope and limits.
