# AgentTeams v0.1.21

Host-compatibility release: AgentTeams now targets **DeepSeek Harness `0.1.7-rc.1`**.

The browser half could not span both host generations, so the older host targets were dropped rather than carried as an untested claim. `0.1.20` remains the last release for `0.1.5-rc.1` and earlier.

## Host API migrations

Each of these was confirmed against the published `0.1.7-rc.1` artifacts, not inferred from the version number.

- **`agent/session-start` -> `agent/created`.** `0.1.7` folded the session-start notification into `agent/created`. The event exists in both generations, but its contract changed: `0.1.5-rc.1` declared it as an `emit` notification carrying only `{ agent }`, while `0.1.7-rc.1` declares it as a `serial` listener carrying `{ agent, source, signal? }` whose completion gates agent creation. The member-setup listener therefore returns `undefined` explicitly and stays synchronous, preserving the first-request race guarantee.
- **`MessageSourceMap` lost its catch-all `plugin` kind.** `0.1.7` requires each producer to declare its own kind. AgentTeams now declares an `agent-teams` source in `harness-compat.ts`; user-role messages accept any producer's kind, which is the only role this plugin authors.
- **Icon renames in `dsh-client-ui-primitives`.** `*Outline16` / `*Outline14` became `*OutlineMedium`. The package is a client-bundle external resolved from the host's browser module table, so there is no runtime alias - the names must match the host.
- **`SessionListState.current` removed.** The current Session is now the one retained under the `mainView` source.
- **Session navigation moved out of `ISessions`.** `open` / `openSubagent` / `subagentAddress` were removed with the note "navigation belongs to view owners"; navigation is now `ctx.uiWorkspace.openSession(target)`, whose `SessionTarget` accepts the `SessionId | SubagentAddress` union directly. This retired the plugin's runtime feature-detection for member transcripts.
- **`tool-result` left `ContentBlockMap`.** The tool outcome is now `ToolResultMessage.isError` plus the event's optional `error`.
- **`dsh-code-runtime-worker-thread` removed.** The code-execution seam is now `dsh-ptc-runtime`; the repository's real-host test mounts the shipped `dsh-ptc-runtime-node` backend (with the genuine filesystem, subprocess and sandbox services) so PTC presentation and `run_code` execution are still exercised against real host code.

## Dependency closure

The development and peer baselines moved from `0.1.5-rc.1` to `0.1.7-rc.1`. Two transitive alignments were required, both caught by `dsh-agent-teams-doctor` reporting duplicate resolved identities:

- `@deepseek-ai/cordis` `^4.0.2` -> `^4.0.4` (`0.1.7-rc.1` depends on `~4.0.4`; the old range resolved a second Cordis instance alongside the host's).
- `@deepseek-ai/schemastery` development baseline `^3.18.2` -> `^3.18.4` (the old pin seeded a second `dsh-settings` identity that differed only by schemastery version).

`@deepseek-ai/dsh-client-ui-workspace` is a new required host peer: the client now lists `uiWorkspace` in its `inject` array.

## Verification

- `pnpm typecheck`, `pnpm build` and the full `pnpm verify` suite pass against an exact `0.1.7-rc.1` dependency closure.
- `dsh-agent-teams-doctor` reports 267 checked package identities, no duplicates, and no problems.
- The harness doubles in `scripts/` were migrated together with the source. Doubles that kept emitting `agent/session-start` would have silently stopped exercising the member lifecycle, and the web-approval fixture's duplicate-delivery assertions would have passed vacuously against zero filtered messages.

## Compatibility

| Host | Status |
| --- | --- |
| `0.1.7-rc.1` | recommended |
| `0.1.5-rc.1` and earlier | not supported by this release; stay on plugin `0.1.20` |

Install the host, then the plugin:

```sh
npm install --global @deepseek-ai/dsh@0.1.7-rc.1
dsh plugin --profile <your-profile> add --save-exact @nanmicoder/dsh-agent-teams@0.1.21
```

Restart Harness for that profile, then refresh the browser.
