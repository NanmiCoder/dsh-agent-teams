### DSH-0.1.5-RC2-01 · the feedback surface's injected contract loses `toggle`/`acknowledge` and reshapes `openDialog`

- **Type**: breaking
- **Applies to**: Web Client plugins that take over the `feedback` entry (order 10) of
  `conversation.chat.assistant-actions` or the `feedback-dialog` entry (order 2) of
  `conversation.input.overlay`, or that import `MessageFeedbackInjected`,
  `FeedbackDialogInjected` or `MessageFeedbackToggleResult` from
  `@deepseek-ai/dsh-client-ui-message-feedback/client`.
- **Touchpoints**: #1 for source or type patches against the injected surface; #5 for
  plugin code that drives the feedback controller programmatically.
- **Action level**: required-if-hit
- **Symptoms**: the injected faces introduced one edge earlier do not survive this one:
  - `MessageFeedbackInjected.toggle(messageId, rating)` → `retract(messageId, rating)`,
    and its meaning narrows: it no longer writes the opposite judgment, it deletes only
    while the committed rating still matches and otherwise resolves to a no-op
    (`{ ok: true }`). The return type is `MessageFeedbackActionResult`, not
    `MessageFeedbackToggleResult`.
  - `MessageFeedbackInjected.openDialog(messageId)` → `openDialog(messageId, rating)`;
    the dialog must now know which judgment it is confirming.
  - `MessageFeedbackInjected.acknowledge()` is gone. `FeedbackDialogController` raises
    the acknowledgement itself after a successful submission and `acknowledge()` is now
    private.
  - `MessageFeedbackToggleResult` is no longer exported from the package's `client`
    entry, so an existing import fails to resolve.
  - `FeedbackDialogInjected` gains `dismissFailure()`, and `FeedbackDialogTarget`'s
    message branch gains a required `rating`.
  Seat names, orders and props-interface names are unchanged, so a plugin that only
  renders the seats still builds — the break lands on the injected members.
- **Migration recipe**: for a control that offers both judgments, branch on the committed
  item first and call `retract(messageId, rating)` only while
  `current(messageId)?.rating === rating`; otherwise call `openDialog(messageId, rating)`
  and let the dialog's Submit write the record. Drop every `acknowledge()` call, replace
  the removed result type with `MessageFeedbackActionResult`, stop reading a returned
  rating, and wire `dismissFailure` where the failure toast should be retired. This card
  supersedes the `openDialog(messageId)` / `acknowledge()` / `toggle`-result half of the
  `ui-message-feedback` card on the `0.1.5-alpha.1 → 0.1.5-alpha.2` edge, which is still in
  an open pull request: read the two together, and take this file's shape once both land.
- **Verification**: typecheck passes against `retract` and
  `openDialog(messageId, rating)`; clicking a recorded rating retracts it without opening
  the dialog; clicking an unrecorded rating opens the dialog and writes nothing until
  Submit; no stale import of `MessageFeedbackToggleResult` remains.
- **Source**: [rc.2 `packages/client/ui-message-feedback/src/client/slots.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-rc.2/packages/client/ui-message-feedback/src/client/slots.ts) · [rc.2 `.../src/client/index.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-rc.2/packages/client/ui-message-feedback/src/client/index.ts) · [rc.2 `.../src/client/controller.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-rc.2/packages/client/ui-message-feedback/src/client/controller.ts) · [rc.2 `.../src/client/dialog.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-rc.2/packages/client/ui-message-feedback/src/client/dialog.ts)

### DSH-0.1.5-RC2-02 · both ratings confirm in the dialog, and a failed submission becomes a warning toast

- **Type**: behavior
- **Applies to**: Web Client plugins that mount, replace or drive the feedback surface
  (`ui-message-feedback`), and every test or automation that assumed a Like records on
  click.
- **Touchpoints**: #5; #3 for end-to-end suites that assert the feedback flow.
- **Action level**: required-if-hit
- **Symptoms**: on rc.1 a Like recorded immediately (one `messageFeedback` mutation plus
  the acknowledgement toast) and only a Dislike opened the dialog. On rc.2 one
  `choose(rating)` path serves both buttons: a matching committed rating retracts, any
  other state opens the dialog with that rating, and the record is written on Submit —
  an empty draft is still a valid submission. Submission failure also moves out of the
  dialog body: the draft stays open and its code is published as a 6-second warning
  toast in the same `conversation.input.overlay` entry, retired through
  `dismissFailure()`; a failure resets the acknowledgement toast sequence, and the two
  toasts never render together.
- **Migration recipe**: if you drive the surface programmatically, stop treating Like as
  fire-and-forget — expect a dialog target with `rating` instead. If you assert the flow
  in tests, replace "Like records immediately" with "Like opens the dialog, Submit
  records" and assert the failure copy on the toast rather than inside the modal. Keep
  the dialog's category/note contract unchanged; it is the same seven chips.
- **Verification**: a Like opens the dialog and records nothing until Submit; a recorded
  Like and a recorded Dislike both retract on click; a forced submission failure keeps
  the draft, shows the warning toast for its hold window, and closes it through
  `dismissFailure` without closing the modal.

### DSH-0.1.5-RC2-03 · `FileTypeIcon`'s code-category artwork is replaced by the design export and renders through injected markup

- **Type**: behavior
- **Applies to**: Web Client plugins that render `FileTypeIcon` (deliverables cards, file
  chips, custom file lists) or that assert on its rendered markup, and any plugin that
  bundles a copy of the code-file glyphs.
- **Touchpoints**: #5; #3 for DOM or string snapshots of the icon.
- **Action level**: conditional
- **Symptoms**: the 477-line hand-written artwork `switch` inside `CodeFileIcon` is gone
  (the file now adds 14 lines). Each of the 48
  `CodeFileType` categories now comes from the new `code-file-icon-artwork.ts` table,
  which is injected with `dangerouslySetInnerHTML` after replacing a
  `__DSH_CODE_ICON_INSTANCE__` token with a per-instance `dsh-code-icon-*` id, so
  gradients and clip paths stay independent between two icons of the same type. The
  artwork itself is a new internal design export, recorded with `sha256` digests in
  `code-file-icon-artwork.manifest.json` (which also lists the deliberately excluded
  `markdown`), so every code and configuration icon changes appearance — a light plate,
  thinner brand artwork and a baked palette. `FileTypeIcon` keeps its props and its
  selection rule (`isCodeFileType(type) ? CodeFileIcon : glyph(type)`), so only the
  traditional set — the generic and `code` glyphs, Excel, folder, HTML, image, Markdown,
  PDF, PPT, video and Word — still honours `--dsh-file-type-icon-color`; the 48 artwork
  categories, letterform ones such as `css`/`env`/`ini`/`toml`/`yaml` included, keep their
  embedded palette.
- **Migration recipe**: no source change is needed to keep rendering. If you assert on
  the output, normalize or drop the instance id (`dsh-code-icon-*` differs per render)
  and refresh the expected markup. If you re-implement the code glyphs, keep using the
  public `FileTypeIcon` instead of copying SVG paths — the artwork is a closed set that
  the package test pins to `CODE_FILE_TYPES`, and its table is reachable but internal
  through the package's `./src/*` subpath.
- **Verification**: a code file yields the same artwork through `kind` and through `path`
  classification once instance ids are normalized; no snapshot contains a hardcoded
  `dsh-code-icon-` id; `--dsh-file-type-icon-color` still tints a traditional glyph such
  as the generic file.
- **Source**: [rc.2 `packages/client/ui-primitives/src/CodeFileIcon.tsx`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-rc.2/packages/client/ui-primitives/src/CodeFileIcon.tsx) · [rc.2 `src/code-file-icon-artwork.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-rc.2/packages/client/ui-primitives/src/code-file-icon-artwork.ts) · [rc.2 `src/code-file-icon-artwork.manifest.json`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-rc.2/packages/client/ui-primitives/src/code-file-icon-artwork.manifest.json) · [rc.2 `tests/code-file-icon.client.spec.tsx`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-rc.2/packages/client/ui-primitives/tests/code-file-icon.client.spec.tsx)

### DSH-0.1.5-RC2-04 · the completed-turn footer and file-section spacing become a documented contract

- **Type**: behavior
- **Applies to**: Web Client plugins that contribute to the `conversation.chat.turnTail`
  hole — the seat `ui-deliverables` occupies and declares against `ui-conversation` — or
  that render their own file list into a finished turn's tail.
- **Touchpoints**: #5
- **Action level**: optional
- **Symptoms**: the two built-in tail renderers stop carrying their own 16px top margins
  and lean on the chat flow instead. `ui-chat` gives the action footer a `margin-top:
  4px` and documents "the completed-turn action footer starts 20px below the preceding
  prose or extension content"; `ui-deliverables` drops both of its own top margins to 4px
  (the produced-files row and the delivery grid), zeroes the grid's again when a
  produced-files row already precedes it
  (`data-after-produced-files`), and documents the chain "first file section 20px below
  the closing prose, a following explicit-delivery section 16px below the row, action
  footer 20px below the last file section". The delivery grid also tightens: 10px gaps,
  60px cards, a 40px icon frame holding a 20px `FileTypeIcon`, 13px filename and 10px
  secondary text.
- **Migration recipe**: do not add your own 16px spacer at the top of a turn-tail
  contribution — the flow supplies the separation, and a second consecutive file section
  keeps the 16px offset instead. Re-check hardcoded row heights, icon sizes and grid gaps
  against the 20px/40px frame when your contribution sits in the same tail.
- **Verification**: with `ui-deliverables` and one custom contribution mounted, the
  closing prose → first section → second section → action footer gaps read 20/16/20px at
  default zoom, and a long delivery list stays inside its own section instead of pushing
  the footer away.
- **Source**: [rc.2 `packages/client/ui-chat/README.md`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-rc.2/packages/client/ui-chat/README.md) · [rc.2 `ui-chat/src/client/chat/TurnTailNodeView.module.css`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-rc.2/packages/client/ui-chat/src/client/chat/TurnTailNodeView.module.css) · [rc.2 `packages/client/ui-deliverables/README.md`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-rc.2/packages/client/ui-deliverables/README.md) · [rc.2 `ui-deliverables/src/client/Deliverables.tsx`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-rc.2/packages/client/ui-deliverables/src/client/Deliverables.tsx)

### DSH-0.1.5-RC2-05 · the `service-stability` feedback category is re-labelled in both languages

- **Type**: behavior
- **Applies to**: Web Client plugins and documents that surface the feedback category
  list, duplicate its copy, or anchor on the displayed text of the `/feedback` dialog and
  the feedback row.
- **Touchpoints**: #5; #7 for anything that matches localized interface text.
- **Action level**: conditional
- **Symptoms**: the locale key does not move, but its copy does — `category.service-stability`
  is `Stability and speed` (English) and `稳定性和速度` (Chinese) where rc.1 said
  `Service stability` / `服务稳定性`. The `command-feedback` README table and the feedback
  subsystem docs change with it. The seven category ids are unchanged:
  `task-result`, `instruction-following`, `product-interaction`, `service-stability`,
  `resource-cost`, `security-privacy-permission`, `other`.
- **Migration recipe**: keep addressing categories by id and keep reading the label from
  the `feedback` locale seat instead of hardcoding it. Refresh any duplicated copy,
  screenshot, fixture or text selector that matched the retired strings — a UI test that
  clicked the chip by visible text is the realistic casualty.
- **Verification**: the dialog lists the same seven ids with the new `service-stability`
  label in both languages, and a search for the retired strings in your own repository
  comes back empty.

- **Touchpoints**: none.
- **Action level**: informational
- **Symptoms**: of the 334 changed files, 272 are `package.json` files whose only
