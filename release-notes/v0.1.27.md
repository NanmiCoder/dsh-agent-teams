# v0.1.27 — Harness rc.3 support and upgrade reliability

This stable plugin release adds support for Harness `0.2.1-rc.3`, fixes Windows packaging and verification, and reduces omissions when validating future host versions. The recommended host remains `0.2.1-rc.2`; all previously supported hosts remain in the compatibility matrix.

- Accept the exact rc.3 host after source/artifact auditing and real installation verification.
- Fix Windows line-ending and runtime-fixture handling; verify rc.2 and rc.3 on Windows in addition to the Ubuntu host matrix.
- Generate peer declarations from one compatibility policy. New host targets default to real plugin installation and Ubuntu/Windows evidence, and the report collector requires those results.
- Add a read-only upstream/release status check and prevent broad `engines.dsh` declarations from bypassing the exact support policy.

## Install or update the latest version

**Desktop installation during the first 24 hours:** pnpm 11 can resolve npm `@latest` to an older release because of its default minimum release age. The preview can show the new version while installation rejects the old one. To install immediately without editing configuration or pinning a numeric version, enter `github:NanmiCoder/dsh-agent-teams` in **Plugins → Add plugin**. This requires GitHub access. Changing npm mirrors does not remove the waiting period.

**桌面端发布首日安装提示：** pnpm 11 的默认等待期可能让 `@latest` 仍选中旧版，造成“预览新版、安装旧版”的矛盾。立即安装请在「添加插件」输入 `github:NanmiCoder/dsh-agent-teams`，无需手改配置或填写版本号；需要能访问 GitHub。也可等发布满 24 小时后再从 npm 安装，换镜像不能消除等待期。

In desktop plugin settings, use the GitHub spec above, or enter `@nanmicoder/dsh-agent-teams@latest` for npm after the waiting period, and enable it. The desktop app manages its own Harness core; check its version against the support matrix.

For a CLI-managed profile, use npm `latest`:

```sh
dsh plugin --profile web add --save-exact @nanmicoder/dsh-agent-teams@latest
```

Or use the GitHub default branch, without a tag or commit suffix:

```sh
dsh plugin --profile web add github:NanmiCoder/dsh-agent-teams
```

Use the `@latest` channel explicitly for npm updates: a bare package name can retain an already installed exact version. If a mirror has not synced, append `--registry=https://registry.npmjs.org`. Run the selected command again when updating, then restart that profile's Harness process and refresh the browser. GitHub default-branch code may be newer than npm `latest`; the host and plugin also have independent release channels. These commands select the current source at installation time and do not enable background auto-updates.

## Validation scope

The release pipeline verifies one candidate package across 11 exact host versions on Ubuntu plus rc.2/rc.3 on Windows. Runtime scenarios use the real Harness CLI, plugin, tools, sessions and subagents with a deterministic model fixture. They cover installation where declared, lifecycle, FIFO delivery, cold restore, fallback, failure handling, approval, protocol behavior and stability. This does not establish real-provider behavior, native Desktop interaction or migration of existing user data.

See [compatibility.json](../compatibility.json), [rc.3 audit](../docs/harness-0.2.1-rc.3/README.md), and [upgrade reliability experiments](../docs/upgrade-reliability-2026-10-26/README.md).
