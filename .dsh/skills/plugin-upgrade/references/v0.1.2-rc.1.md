  `emit_preset` → `emit_app` → `verify_app` → `deploy_app` through the host's own tool

## Backfill candidates (not part of this edge)

Three items from the rc.1 summary are **not carded anywhere** in the corridor. None is a
breaking change on this edge (rc.1 differs from alpha.5 by nothing), so they are recorded
here as candidates for older-edge backfills rather than as rc.1 cards:

1. **SQLite Session-persistence backend removal** — a profile/configuration surface change
   that shipped earlier in the 0.1.2 series (the alpha.2 → alpha.3 edge carded zero cards
   and did not record it). Profiles that route session persistence to the sqlite backend
   must export/rebuild before upgrading; the alpha.2 card [DSH-0.1.2-A2-01](v0.1.2-alpha.2.md)
   already notes the sqlite provider's schema-20-only stance, but the backend's removal is
   not carded. Candidate: an alpha.3-edge backfill card (same class as the open
   alpha.3 settings-card backfill), stating when the removal landed and the export path.
2. **File-edit tool `null` placeholder tolerance** — host-tool schema tolerance, low impact
   for plugin authors; informational only.
3. **Experimental Inspector / Web Preview** — new capability surfaces; plugins that want to
   integrate them should check the rc.1 tag's packages directly (no card because no
   migration is required and the surface is experimental).
