### DSH-0.1.5-A1-01 · Session log format moves to V3 (`session-format-v2-to-v3`); `EpochHeader.system` removed and upgraded sessions are not downgrade-readable

- **Type**: breaking
- **Applies to**: integrations that read stored Session logs (raw JSONL archives,
  analysis/export tooling), out-of-tree `ctx.sessionPersistence` providers, custom
  `session-format` stages, and any plugin that hand-parses session artifacts.
- **Touchpoints**: #2, #4
- **Action level**: required-if-hit
- **Symptoms**: `SESSION_FORMAT_VERSION` becomes `3`
  (`packages/core/session/src/types.ts`); the new package
  `@deepseek-ai/dsh-session-format-v2-to-v3` (absent at `0.1.3-alpha.2`) is the single
  specification for this adjacent edge, and the catalog gains
  `currentVersion: 3` / `currentEncoder: releasedV3SessionFormatCodec` plus the
  `sessionFormatV2ToV3` migration. Restoring a supported released V2 Session produces a V3
  log without changing historical request meaning: system prompts are promoted into
  messages, local event references are remapped, PTC/preset vocabulary is translated, and
  envelopes are canonicalized. The original artifact is preserved, but an upgraded Session
  **cannot be read by older builds**. Related contract changes land in the same window:
  `EpochHeader.system` is removed (a `request/header` carrying `header.system` — even an
  empty string — now throws `must omit header.system; use system/message`), the V3 reader
  requires `surfaceOp` on the four surface event families, and `session-format`'s
  `sourceCut` becomes optional (validated at `finish()`).
- **Migration recipe**: read through the official surface (`SessionHandle` `read`, or
  `seq`/`eventAt()`/`snapshotEvents()`) instead of parsing artifacts by hand. Custom log
  readers must follow the V2→V3 specification: a synthetic empty `system/message` head is
  appended after the first `step/start` (sessions with no steps get no head), `'code'`
  preset references in `header.agentPreset` and `agent-preset/selected` become `'ptc'`
  (never touching `run_code`'s `code` argument or `:code:` ids), and reference remapping
  covers `sourceEventSeqs[]`, `surfaceOp.start/end`, `command/done.sourceEventSeq`,
  `compaction.*` ranges and `session/title*.messageSeqs[]`. Keep a `0.1.3-alpha.2`
  installation if old logs must still be read — downgrade reading is not supported.
  Providers implementing persistence must store the catalog's current format.
- **Verification**: a V2 session with real history restores on `0.1.5-alpha.1`; the
  original artifact remains on disk; the restored session reads correctly through the
  official APIs; a `request/header` with `system` is rejected; opening the upgraded session
  with an older build is refused. The package's own
  `packages/session/session-format-v2-to-v3/tests/*` and
  `packages/session/session-persistence-jsonl/tests/{v2-ptc-migration,v2-system-migration,migration-refusal,v3-event-admission}.spec.ts`
  are the behavior baseline.
- **Source**: [alpha.1 `session-format-v2-to-v3` README (single specification)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/session/session-format-v2-to-v3/README.md) · [alpha.1 `SESSION_FORMAT_VERSION = 3` and `EpochHeader`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/core/session/src/types.ts) · [alpha.1 `session-format-catalog/src/generated.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/session/session-format-catalog/src/generated.ts) · [alpha.1 `session-persistence-jsonl/src/format.ts` (V3 admission)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/session/session-persistence-jsonl/src/format.ts) · [0.1.5-alpha.1 release notes (Session format V3; no downgrade read)](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.5-alpha.1) · earlier format edges: [v0.1.3-alpha.1.md](v0.1.3-alpha.1.md)

### DSH-0.1.5-A1-02 · `ctx.agent` removed (runtime trap) — pass the Agent explicitly and declare `parentAgent`

- **Type**: breaking
- **Applies to**: plugins/services that read `ctx.agent` or `agent.ctx.agent`, implement
  `AgentSetup`, or create/resume agents relying on implicit ownership.
- **Touchpoints**: #3
- **Action level**: required-if-hit
- **Symptoms**: `AgentRegistry` no longer registers a `ctx.accessor('agent', …)` and
  `ReactLoopAgent` no longer extends its context with `{ agent: this }`
  (`packages/core/agent/src/index.ts`, `packages/core/agent-loop/src/agent.ts`), and the
  `Context` module augmentation drops `agent?: Agent`. Reading `ctx.agent` now **throws at
  runtime** — cordis's proxy trap raises `cannot get property "agent" without inject`
  (`vendor/cordis/src/reflect.ts`) — not `undefined`. `AgentSetup` gains an explicit second
  parameter: `(agentCtx: Context, agent: Agent) => AgentSetupCommit | Promise<…> | void`,
  and `CreateAgentOptions` / `ResumeAgentOptions` gain `parentAgent?: Agent` ("live parent
  Agent for runtime ownership; omit for a root Agent"). `AgentRegistry.register()` now
  enters with an explicit `undefined` root instead of `ctx.agent`, which is the ownership
  fix: continuable subagents are no longer treated as root sessions participating in
  scheduled work.
- **Migration recipe**: delete every `ctx.agent` / `agentCtx.agent` read. Choose one of:
  (a) the `AgentSetup` second parameter `(agentCtx, agent)`; (b)
  `ctx.agents.currentInitiator()` where an optional shape is acceptable; or (c) pass the
  Agent explicitly into your service methods (the new API style, e.g.
  `workspaceFiles.read(agent, …)`, `goals.get(agent)`). Update `AgentSetup`
  implementations to the two-parameter signature, and pass `parentAgent` explicitly when
  creating/resuming child agents (omit for roots) — do not infer root-vs-child from
  context nesting.
- **Verification**: `rg "ctx\.agent|agentCtx\.agent"` returns nothing in your plugin;
  typecheck passes with the new `AgentSetup`; `dsh --profile <p> --dump-config` and a real
  boot work; create/resume with and without `parentAgent` shows the expected ownership
  (continuable subagents are not scheduled as roots).
- **Source**: [alpha.1 `core/agent/src/index.ts` (no accessor; new `AgentSetup`, `parentAgent`, explicit root)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/core/agent/src/index.ts) · [alpha.2 `core/agent/src/index.ts` (augmentation and accessor present)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.3-alpha.2/packages/core/agent/src/index.ts) · [alpha.1 `agent-loop/src/agent.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/core/agent-loop/src/agent.ts) · [alpha.1 cordis inject trap](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/vendor/cordis/src/reflect.ts) · [0.1.5-alpha.1 release notes (plugin Agent API change)](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.5-alpha.1)

### DSH-0.1.5-A1-03 · `Inbox` becomes a type interface reachable as `agent.inbox`; the runtime class and public `hasPending`/`claim` are gone from the type surface

- **Type**: breaking
- **Applies to**: plugins that imported or constructed the `Inbox` runtime class from
  `@deepseek-ai/dsh-agent`, or that relied on `hasPending`/`claim` as public queue APIs.
- **Touchpoints**: #2, #3
- **Action level**: required-if-hit
- **Symptoms**: `packages/core/agent/src/inbox.ts` is deleted at `0.1.5-alpha.1` and the
  package barrel no longer re-exports it, so `import { Inbox } from
  '@deepseek-ai/dsh-agent'` no longer has a runtime export; `hasPending` and `claim` are
  removed from the public `Inbox` interface (`packages/core/agent/src/runtime-types.ts`
  now declares only `nextTurn`/`nextStep`/`clear`/`append`/`prepend`/`replace`/`remove`/
  `splice`). Note the failure mode is **type-level, not a runtime crash**: the driver
  implementation (`ReactLoopInbox` in `packages/core/agent-loop/src/inbox.ts`) still has
  those methods at runtime. In the same window the queue becomes projection-driven: a new
  session-projection key `inbox` (`inboxProjectionDefinition`, `stateVersion: 1`,
  consuming `agent/inbox/spliced`) is registered by the driver, and the Web queue frame is
  broadcast from `ctx.sessionProjections.onChanged` when `key === 'inbox'` instead of
  listening to `session/event` — so the projection exists only while an agent loop is
  active.
- **Migration recipe**: treat `Inbox` as a type only; access pending messages through the
  typed `agent.inbox` interface and drop imports from `@deepseek-ai/dsh-agent/inbox`.
  Compute pending state yourself (`nextTurn.length + nextStep.length > 0`) instead of
  calling `hasPending`, and never call `claim` — claiming is a driver-owned turn-boundary
  operation. Plugins that want the queue as data can read
  `ctx.sessionProjections.stateOf(session, 'inbox')` (wire shape `InboxWireState`); note
  the projection is absent when no agent loop is active. Test doubles can use
  `@deepseek-ai/dsh-agent-loop-testkit` (`createInboxStub()` / `unsupportedInbox()`).
- **Verification**: typecheck passes with no `@deepseek-ai/dsh-agent/inbox` imports and no
  `hasPending`/`claim` calls; queueing a message through `agent.inbox` delivers it at the
  next-turn/next-step boundary; a client built on the `inbox` projection updates after the
  splice commits (not on the raw event) and behaves correctly when no loop is active.
- **Source**: [alpha.1 `agent-loop/src/inbox.ts` (driver-owned projection, `ReactLoopInbox`)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/core/agent-loop/src/inbox.ts) · [alpha.2 `core/agent/src/inbox.ts` (class still present)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.3-alpha.2/packages/core/agent/src/inbox.ts) · [alpha.1 `core/agent/src/runtime-types.ts` (public Inbox interface)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/core/agent/src/runtime-types.ts) · [alpha.1 `session-controller/src/control.ts` (queue from projection)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/api/session-controller/src/control.ts) · [0.1.5-alpha.1 release notes (Inbox API change)](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.5-alpha.1)

### DSH-0.1.5-A1-04 · session event payload validation tightens (`surfaceOp` `startSeq`/`endSeq`, `SurfaceIntent` typing, `tool/result` error consistency, empty header fields, opaque wire fields)

- **Type**: breaking
- **Applies to**: plugins that append or seed session events (compaction, pruning,
  replacement, custom tool/result writers), and Web Client integrations that parse
  session-wire events.
- **Touchpoints**: #2, #6
- **Action level**: required-if-hit
- **Symptoms**: five validation changes land together in
  `packages/core/session/src/{types.ts,surface.ts,request-header.ts}` and
  `packages/api/session-controller/src/{types.ts,client/session-wire-event.ts}`:
  (1) `SurfaceOp` replace uses `startSeq`/`endSeq` instead of `start`/`end` — `isReplaceOp`
  only accepts the new keys, so old payloads fail validation;
  (2) surface event types move to `SurfaceIntent<K>` with a required `surfaceOp`, while
  log-only events declare `surfaceOp?: never; sourceEventSeqs?: never` — passing a
  `surfaceOp` to a log-only event is now a compile-time error;
  (3) a `tool/result` carrying `data.error` must have
  `message.content[0].isError === true`, otherwise append/seed/adopt throws (contradictory
  results are no longer silently accepted);
  (4) `request/header` must omit empty `tools: []` and `adapterDefaults: {}` ("must omit
  empty tools" / "must omit empty adapterDefaults"), enforced by `canonicalHeader()`;
  (5) `SessionWireEvent.sourceEventSeqs`/`surfaceOp` are typed as opaque `JsonValue` and a
  new client-side `assertSessionWireEvent()` validates every event in snapshot,
  notification and history lanes — unknown fields throw, and clients that hard-coded
  `surfaceOp.start/end` break.
- **Migration recipe**: rewrite replace ops to `{ op: 'replace', startSeq, endSeq }` and
  keep `sourceEventSeqs` non-empty, unique and strictly earlier than the new event. Only
  `system/message` may rewrite the protected node 0, and only when the replacement covers
  that exact node. Emit system prompts as `system/message` (never as `header.system`),
  clear empty arrays/objects from headers, and keep `tool/result.error` consistent with
  `content[0].isError: true`. On the wire, narrow `JsonValue` per event type yourself —
  the host-side `validateSessionEventData`/`validateSurfaceMetadata` are not importable
  from the client.
- **Verification**: appending a replace op with `start`/`end` is rejected; the same op with
  `startSeq`/`endSeq` succeeds; a `tool/result` with `error` and `isError: false` is
  rejected; a header with `tools: []` is rejected; a client parsing wire events with the
  new opaque fields handles unknown-field errors deterministically.
- **Source**: [alpha.1 `core/session/src/surface.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/core/session/src/surface.ts) · [alpha.1 `core/session/src/types.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/core/session/src/types.ts) · [alpha.1 `session-controller/src/client/session-wire-event.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/api/session-controller/src/client/session-wire-event.ts) · [alpha.1 `core/session/src/request-header.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/core/session/src/request-header.ts) · [0.1.5-alpha.1 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.5-alpha.1)

### DSH-0.1.5-A1-05 · PTC vocabulary rename (`tool/ptc-dispatch`, plugin `tools-ptc`, `<parent>:ptc:<n>`)

- **Type**: breaking
- **Applies to**: log readers, UI filters and analytics that select PTC/code-mode events,
  and any plugin that inspects `subCallId` or the `source.plugin` marker.
- **Touchpoints**: #2, #5
- **Action level**: required-if-hit
- **Symptoms**: the session event names `tool/code-dispatch` and
  `tool/code-dispatch-start` become `tool/ptc-dispatch` and `tool/ptc-dispatch-start`
  (`packages/core/session/src/known-event-types.ts`,
  `packages/core/tools/src/types.ts`), the emitting plugin marker
  `source.plugin: 'tools-code-mode'` becomes `'tools-ptc'` in `user/message`,
  inbox-inserted messages and `title-llm-request`, and new sub-call ids use the
  `<parent>:ptc:<n>` prefix (`packages/core/tools/src/ptc.ts`). Historical ids still
  contain `:code:`, so prefix parsing must not assume one generation.
- **Migration recipe**: update event filters, dashboards and invariants to the new names
  and the new plugin marker; parse sub-call ids by suffix/generation rather than a fixed
  `:code:`/`:ptc:` prefix. Where old logs are archived, normalize both generations at read
  time (the V2→V3 migration translates the vocabulary for supported history, but raw
  archives read outside the migration still carry the old names).
- **Verification**: a PTC round-trip produces `tool/ptc-dispatch` events with
  `source.plugin: 'tools-ptc'` and `<parent>:ptc:<n>` ids; a reader handles both old and
  new generations without dropping rows.
- **Source**: [alpha.1 `core/session/src/known-event-types.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/core/session/src/known-event-types.ts) · [alpha.1 `core/tools/src/types.ts` (renamed event keys)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/core/tools/src/types.ts) · [alpha.1 `core/tools/src/ptc.ts` (plugin marker and sub-call id)](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.5-alpha.1/packages/core/tools/src/ptc.ts) · [0.1.5-alpha.1 release notes (PTC/preset vocabulary migration)](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.5-alpha.1)

- **Type**: breaking
- **Applies to**: plugins that compute context/token usage from the `token-meter` exports

- **Touchpoints**: #3, #4
- **Action level**: required-if-hit
- **Symptoms**: `packages/llm/token-meter/src/estimate.ts` no longer exports

  own copies.
- **Verification**: typecheck passes with no `estimateHeader`/`estimateSystemTokens`
  imports; token/context numbers for a session with a system prompt match a manual
  surface-node calculation; a pre-upgrade checkpoint row for `contextBreakdown` is
  discarded/rebuilt rather than crashing the boot.

### DSH-0.1.5-A1-07 · system prompts move into message history (`system/message`), enabling dynamic prompt updates without KV-cache invalidation

- **Type**: behavior
- **Applies to**: plugins that contribute system-prompt sections, adapters that declare
  prompt handling, and clients that render or diff the prompt.
- **Touchpoints**: #2, #3
- **Action level**: conditional
- **Symptoms**: a new `system/message` event
  (`{ turn; step; message: SystemMessage }`) carries the system prompt as a surface node;
  the first prompt occupies node 0 and is appended even when empty. A capable route
  (`systemPromptUpdate: 'in-history'`) appends changed **non-empty** prompts after the
  cached history within a continuous request sequence, so the KV cache stays valid; an
  incapable route or a new sequence normalizes the latest text onto node 0. Node 0 is
  protected: a replace covering it must itself be a `system/message` and cover exactly that
  node. `request/context` gains `systemPromptUpdate?` (appended only when
  provider/model/contextWindow/mode change), and prepared capability — not the previous
  snapshot — decides admission. New types: `SystemMessage`,
  `createSystemMessage(text, plugin)` (`''` → `content: []`), `SystemPromptUpdate =
  'in-history'`, `LlmResolvedModelInfo.systemPromptUpdate?`,
  `PreparedLlmCall.systemPromptUpdate?`. `dsh-llm-deepseek`'s catalog accepts
  `systemPromptUpdate: 'in-history'`, and the pi-ai adapter's `splitSystemPrompt()`
  prefers `options.system`, otherwise the first system history message, folding the rest
  into user messages to preserve order. Two related narrowing/removal changes:
  `LlmCallConfig.system` **stays** but is re-documented for one-shot callers only —
  adapters map it to the provider's system slot ahead of `messages`, and loop-built
